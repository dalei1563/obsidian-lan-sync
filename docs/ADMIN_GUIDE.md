# LAN Note Sync 0.4 管理台

管理台用于管理这套自建同步服务，访问路径为 `/admin/`。只需要一个管理员密码，没有用户名、注册、邮箱或多账户系统。

0.4.0 双架构镜像已经发布；部署和升级见 [GHCR / 1Panel 指南](ONEPANEL_GHCR.md)。

## 首次打开

在浏览器打开服务地址后追加 `/admin/`，例如 `http://服务器地址:27123/admin/`。使用管理员密码登录。

新部署的安装脚本会自动生成独立管理员密码，写入部署目录的 `.env`：

```ini
SYNC_ADMIN_PASSWORD=安装时生成的密码
```

安装终端会显示新生成的密码，请自行保存。已有有效密码会保留，不会因为重跑脚本而重新生成。管理员密码和 CouchDB 管理员密码、Obsidian 设备凭证各自独立，客户端不需要填写管理员密码。

如果页面显示“后台尚未设置管理员密码”，说明网关尚未收到 `SYNC_ADMIN_PASSWORD`。同步接口可以继续工作；按下文为旧部署补齐环境映射并重建网关。

## 管理台能做什么

| 页面 | 功能 |
| --- | --- |
| 同步总览 | 仓库数、当前文件数、已授权设备、并发冲突、正文占用和最近变更 |
| 笔记仓库 | 创建、重命名仓库，查看统计，为指定仓库生成连接码和安装命令，配置排除规则 |
| 同步记录 | 按仓库筛选文件新增、更新、移动、删除和冲突解决记录，分页读取历史 |
| 设备管理 | 查看设备属于哪个仓库、授权状态及本次服务启动后的最近活动，单独撤销设备 |
| 服务设置 | 查看服务版本、数据库、运行时间及服务标识，退出当前管理会话 |

“同步记录”是服务端已经接收的文件业务修订，不等同于客户端的所有同步尝试。设备断网、连接失败、打开中的笔记或本地待上传项，应在对应 Obsidian 插件中查看。旧版本没有保存时间的历史记录会显示时间未知，不推测创建时间。

“已授权”不等同于实时在线。撤销某台设备会阻止它继续访问对应仓库，但保留已经提交的笔记和历史。重新使用该设备时需要生成新邀请。

## 多仓库与设备接入

服务可以同时管理多个独立远端仓库。每个本地 Obsidian Vault 都分别安装插件、保存自己的连接与同步基线：

- 多台电脑可以连接同一个远端仓库，组成一套笔记的多设备同步。
- 不同的本地 Vault 可以分别连接不同远端仓库，笔记、版本和设备授权相互隔离。
- 一台电脑可以打开多个 Vault；本版每个本地 Vault 只绑定一个远端仓库。

在“笔记仓库”中创建或打开目标仓库，点击“连接设备”。页面会根据当前浏览器访问的服务地址生成完整连接码，以及 Windows/macOS 安装命令，无需再手动拼接 IP 和端口。

将对应命令放到要连接的电脑上执行，选择本地 Vault，再在 Obsidian 中启用 LAN Note Sync。安装后会自动读取连接信息，并先展示首次同步预览；用户确认后开始同步。每台设备分别生成邀请，邀请 10 分钟有效。

插件已安装但未绑定时，也可在插件设置中直接粘贴完整连接码。已经绑定的 Vault 不应通过删除状态文件来切换仓库；先保留原笔记和完整插件状态，按迁移流程处理。

重命名远端仓库只改变后台显示名称，不改变仓库 ID 或现有设备授权。客户端中保存的仓库名称可能在重新接入前仍显示旧名称。

## 排除同步

排除规则有两处来源：

1. 后台仓库详情中的“排除同步”：适用于连接该仓库的配套插件。
2. Obsidian 插件设置中的“本机额外排除规则”：只适用于当前本地 Vault。

两者取并集；被任意一条规则匹配的路径都会暂停同步。`.obsidian`、当前 Obsidian 配置目录以及隐藏路径固定排除，不会因为自定义规则为空而放行。

规则每行一条，使用相对于 Vault 根目录的路径。支持 `*`、`?`、独立路径段 `**`，以及表示目录的末尾 `/`。例如：

```text
私人笔记/
**/草稿/**
**/*.tmp.md
工作/暂存.md
```

最多 64 条规则，每条最长 256 字符。不支持绝对路径、`..`、正则表达式、方括号或大括号扩展。空行会忽略。

**新增排除规则会暂停相关路径的上传、下载和删除，不会删除本地文件，也不会自动清理之前已经同步的云端内容。** 既有待上传快照会保留，排除期间不发布；重新纳入时继续核对版本。如果文件在暂停期间两端都有变化，仍可能需要选择版本。

排除规则是同步范围设置，不是仓库内的访问权限划分。需要对设备严格隔离的数据，应使用不同远端仓库。

后台规则需要 **0.4 或更新版本插件**才能在客户端完整执行。旧插件不能识别新策略，升级服务端后应同步升级各设备插件，不能只更新后台就认定旧设备已遵守排除规则。

旧插件仍可能下载既有内容，或在提交被拒绝前上传未引用的正文。规则改变也可能发生在正文上传与提交之间，因此排除不能用于保证敏感内容从未进入服务器。已经排队的不可变快照按原路径暂停；如果原路径被排除，随后改名也不会擅自改写这个快照，需要恢复允许原路径后才能继续。服务回滚到不支持规则的版本时，新插件保留最近一次规则；由支持规则的服务明确保存空规则，才会清除缓存。

## 旧部署升级

升级前保留部署目录、数据库和网关状态，尤其是原 `.env`、数据路径与网关身份。保持原 Compose 项目名和挂载，不要把升级当作新建一个空部署，也不要删除数据卷。

推荐使用新版本包中的 `deployment/setup-images.sh`，在确认镜像已发布后显式升级。以下 `VERSION` 和包路径均需替换为实际值，`--out` 必须指向原有部署目录：

```bash
bash /path/to/new-package/deployment/setup-images.sh \
  --image-prefix ghcr.io/dalei1563/obsidian-lan-sync \
  --version VERSION \
  --out /data/lan-note-sync/deployment \
  --upgrade
```

`--upgrade` 用于明确更新既有部署，不是搬迁数据盘的选项。自定义过 Compose 项目名、端口或其他服务设置的部署，应先核对升级脚本的检查结果；不要绕过存储一致性检查。

也可以手动更新原部署配置。在 `.env` 中设置已发布网关镜像版本和管理员密码，并在 Compose 的 `sync.environment` 下新增映射：

```yaml
SYNC_ADMIN_PASSWORD: ${SYNC_ADMIN_PASSWORD:-}
SYNC_ADMIN_SECURE_COOKIE: ${SYNC_ADMIN_SECURE_COOKIE:-false}
```

只在 `.env` 增加密码但没有 Compose 环境映射，容器不会收到这个密码。配置完成后，在原编排目录执行：

```bash
docker compose pull sync
docker compose up -d --no-deps --force-recreate --wait sync
```

普通容器重启不会换镜像，也不会重新载入 Compose 环境配置。设备凭证和数据不应因为管理台升级而重置。

客户端升级时先关闭 Obsidian，使用对应新版本安装命令的升级模式：Windows 末尾追加 `-Upgrade`，macOS 末尾追加 `--upgrade`。升级保留当前连接与本地状态；它不会把已经绑定的 Vault 改绑到安装命令中的另一个仓库。

## 修改管理员密码和 HTTP 使用

修改原部署 `.env` 中的 `SYNC_ADMIN_PASSWORD`，长度为 8–256 个字符，再重建 `sync` 容器：

```bash
docker compose up -d --no-deps --force-recreate --wait sync
```

网关重新启动后，浏览器会话失效，需要使用新密码登录。Obsidian 设备令牌独立于管理员登录，不因管理员改密而被撤销。

局域网 HTTP 可以使用管理台，不要求先配置域名或证书。HTTP 场景保持 `SYNC_ADMIN_SECURE_COOKIE=false`。只有通过 HTTPS 使用管理台时，才设置 `SYNC_ADMIN_SECURE_COOKIE=true`；如果在 HTTP 上启用，浏览器不会正常发送该安全 Cookie，可能出现登录后仍未登录的情况。

HTTPS 在反向代理终止时，代理应保留原始 Host、Cookie 和管理路径，转发 `/admin/`、`/v1/` 与安装资源。Cookie、登录会话和管理密码不会作为 Obsidian 配对信息分发。

## 同步范围

本版仍面向 Windows/macOS 桌面端 Markdown 文件。不包含图片、PDF 等附件、移动端、Obsidian 配置同步或端到端加密。管理台的“正文占用”是当前文件正文统计，不等于 CouchDB 数据文件和完整历史的实际磁盘占用。
