# 同步管理台设计

## 视觉与结构

以用户提供的 ima 知识库截图为方向：白底、细分隔线、宽松留白、浅绿选中态、深色主按钮。使用现有管理台和接口，不引入另一套站点或模拟数据。

左侧仅保留固定导航和退出入口；仓库统一在笔记仓库页管理。右侧保留页面标题、主要操作和列表。默认进入服务状态页。次要信息用辅助文字呈现；恢复、撤销和移除保留既有确认流程。

## 页面职责

| 入口 | 内容与操作 |
| --- | --- |
| 服务状态 | 仅保留最近成功连接状态、运行时长、版本、存储后端、正文占用 |
| 笔记仓库 | 搜索、新建、重命名、连接设备 |
| 仓库 → 文件 | 默认显示当前文件；按路径搜索，筛选冲突、已删除或全部文件；查看正文、历史与恢复 |
| 仓库 → 同步记录 | 最近 20 条变更；进入该仓库的完整分页记录 |
| 仓库 → 客户端 | 当前仓库的设备授权、最近活动、升级命令、撤销授权 |
| 仓库 → 设置 | 排除规则、仓库信息、移除仓库 |
| 同步记录 | 跨仓库查看服务端已接收的变更，按仓库筛选、加载更早记录 |
| 客户端 | 按仓库筛选设备；添加连接；获取 Windows/macOS 安装、升级命令与插件 ZIP |
| 服务设置 | 服务信息、管理员会话与配置说明 |

## 客户端流程

添加新连接：选择仓库 → 生成一次性邀请 → 选择平台或复制连接码 → 用户在目标电脑执行 → 启用插件并完成首次同步预览。

升级：选择仓库或设备对应的升级入口 → 获取现有安装器的升级命令 → 退出 Obsidian → 选择原本地仓库执行。安装器保留已有连接与配置；后台仅生成命令，不远程执行升级。

当前凭证模型是“一台设备一个授权”，不是独立用户账号。设备名称用于识别连接人及电脑；同一个人可以有多台设备。用户账号、角色、按人聚合、客户端版本上报需要后续后端能力，不能从现有设备授权推断。

## 状态与边界

- 顶栏每 20 秒检查服务连接；失败显示待检查，不以已授权数量宣称实时在线。
- 同步记录代表服务端已提交文件变更，不代表客户端待上传队列或本地网络错误。
- 仓库及文件支持无数据、无搜索结果、加载中、读取失败等状态。
- 移除仓库、撤销授权、恢复版本沿用原确认与接口校验。
- 手机端导航横向排列，数据表横向滚动；文件和管理任务仍优先面向桌面端。
