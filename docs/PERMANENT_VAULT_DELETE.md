# 永久删除仓库

后台“永久删除仓库”调用 `DELETE /admin/api/vaults/:id`，要求现有管理员会话、CSRF、`confirm: "permanent"` 和完全匹配的仓库名。此前的 `/archive` 接口仍仅用于兼容逻辑归档，不是当前删除按钮的行为。

永久清除仓库正文（包括尚未提交的上传对象）、全部业务历史、同步记录、设备凭证、邀请和仓库配置。客户端本地文件与外部备份不受影响。既有归档仓库也可通过同一接口按原 ID 和名称永久删除。

SQLite 先持久化删除意图并停用连接，再删除该仓库对象目录，在事务中删除关联行，最后整理数据库。CouchDB 在同一写队列中持久化删除意图，按 vaultId 分批 purge 文档及附件，清理内存索引并请求数据库整理。删除期间的上传不能重新生成对象。中断后可重试，服务重启会继续未完成的清理。

CouchDB 磁盘回收是后台整理过程，页面成功不表示文件系统占用立即下降。该功能不是对存储介质或已有备份的安全擦除。[CouchDB purge](https://docs.couchdb.org/en/stable/api/database/misc.html)、[后台整理](https://docs.couchdb.org/en/stable/api/database/compact.html)。

验证：本地全套测试在新增重启续删测试前为 121 通过、14 跳过、0 失败；随后 SQLite 管理测试 8 通过。火影独立临时数据库上运行最新管理测试共 14 项，全部通过，包括两种后端实际数据清除、跨仓库隔离、超过 100 个对象的分页删除、归档后永久删除、中断重启续删与旧凭证失效。

2026-11-15 部署镜像 `lan-note-sync:admin-purge-20261115`，前后既有仓库/设备身份及统计一致，网关和数据库健康，前端和网关构建校验一致。部署未调用现有仓库的删除接口。
