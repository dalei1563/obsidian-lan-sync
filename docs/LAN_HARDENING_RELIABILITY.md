# LAN 同步可靠性检查

## 冲突与覆盖

自动化覆盖了覆盖预览后远端变化、上传时远端并发编辑、下载时本地编辑、批量删除批准后范围变化、冲突确认时新增分支，以及超出 5 MiB 的笔记。测试使用内存 Vault、真实本机 HTTP 网关和 SQLite 后端；**未在真实 CouchDB 上验证**，也不是 Windows/macOS Obsidian 的文件系统并发实测。

## 离线与重启

自动化通过故障注入验证：已持久化的待提交版本先重试，之后最新本地内容作为后续版本提交；上传正文成功但提交前中断时，重启复用同一个修订 ID，不产生重复修订。测试通过重建引擎和持久状态模拟重启，**并非实际强杀进程**；服务端使用 SQLite，**未在真实 CouchDB 上验证**。

当前队列保存已捕获的待提交快照及磁盘上的最新内容，不承诺保存离线期间每一次编辑的中间版本。网络在本轮拉取前就不可用时，本轮不会生成新的队列快照；最新笔记仍由 Obsidian 本地文件保存。需要逐次记录中间版本时，应另行设计可靠的本地版本记录，而不能声称当前队列已提供该能力。

## 错误与提示

同步失败会显示错误并退避重试；手动同步同时弹出提示。状态持久化失败会阻止后续提交并要求修复磁盘后重载。文件应用失败列入待处理项，下一轮可重试；自动更新检查失败现在会提示用户手动检查，同一轮连续失败不反复弹窗，成功后重新允许提示。

自动化使用注入错误模拟状态写入失败和文件占用、HTTP 响应模拟鉴权及 5xx，不能代表真实磁盘满、Windows 文件锁或 macOS 应用行为；这些仍需隔离实机验收。**未在真实 CouchDB 上验证。**

## 接入安全

网关使用连接的源 IP 限流，不采信客户端的转发 IP。配对一分钟内允许 10 次请求，超出返回 429；限流桶达到 1000 个活跃来源时拒绝新来源，过期后允许重试，避免限流表无限增长。多客户端共用反向代理时可能共享限额，部署前需评估。SQLite 和 HTTP 测试覆盖未配对拒绝、跨仓库隔离、撤销及限流；隔离真实 CouchDB 测试另覆盖了设备撤销和跨仓库拒绝，限流等新增故障注入场景**未在真实 CouchDB 上验证**。限流仅为单进程内存状态，重启后重置，也不能替代 TLS、网络隔离和边界防火墙。

## 协议与更新兼容

当前插件在每轮同步和解决冲突前检查服务健康接口的协议版本；版本不匹配时停止而不提交待上传修改。快照和连接码也检查协议号。无法为已经安装的旧插件追补该检查，未来协议升级仍需服务端兼容或明确阻止旧客户端，不能仅依赖新客户端自检。未知本地状态 schema 会明确提示版本不兼容并保留原文件，不执行迁移。

自动更新校验下载并先备份，最后写 manifest；替换多个文件不是单个原子事务。强制断电恰逢替换时可能留下混合版本，需要保留备份并在隔离环境验证恢复；不能将应用级异常回滚等同于断电安全。协议兼容和更新测试使用模拟服务及本机文件，**未在真实 CouchDB 上验证**。

## 符号链接测试

数据目录测试先尝试创建符号链接，仅系统返回权限或不支持错误时跳过；其他错误直接失败。本机 Windows 创建链接返回 `EPERM`，因此该项仍未执行。2026-11-10 Linux 测试机上此用例单独运行 1 项通过，完整测试套件中也通过。Windows 可在已具备创建链接权限的环境重跑；本次未更改系统设置。
