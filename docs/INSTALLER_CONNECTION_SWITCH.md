# 安装时更新或切换仓库

后台和 CLI 新生成的连接命令包含目标仓库 ID 及编码后的显示名称。插件的配对协议仍以服务端一次性连接码为准；显示信息不会替代服务端授权。

- 未连接：安装插件并写入 bootstrap，打开 Obsidian 后连接和预览。
- 已连接到相同服务、相同仓库：仅更新插件，保留现有配置和基线。
- 已有其他连接：显示当前服务、仓库和本次目标，要求选择“仅更新”“切换”或“取消”。选择切换后还须输入“切换”。取消、无终端或无有效确认均不更改原安装。
- 旧命令没有目标仓库信息时可以保留原连接更新；切换要求从后台重新生成命令。

切换时先下载并校验新插件文件。原插件目录整体移到当前 Obsidian 配置目录下的 `lan-note-sync-backups/`，包含旧 data.json、local-state 和未完成的配对记录。新安装不复制这些旧状态，写入 `enabled:false` 和新 bootstrap；笔记文件不做任何操作。最终目录替换失败时尝试还原旧目录。

重启 Obsidian 后，用户仍需完成 HTTP 内网提示（适用时）及首次同步预览。界面“连接配置已写入”不代表新设备已经完成配对。新连接码仍有十分钟有效期。旧远端仓库和旧设备授权不会被安装器删除或撤销。

Windows 使用 Read-Host；通过管道运行的 macOS 命令从 `/dev/tty` 读取选择，避免误读安装脚本文本。Windows 支持 `-ConnectionAction Keep|Switch|Ask` 与 `-ConfirmSwitch`，Bash 支持 `--connection-action keep|switch|ask` 与 `--confirm-switch`，供明确指定行为的自动化使用；后台生成的命令默认交互确认。

验证：本地全套 141 项，126 通过、15 环境跳过、0 失败。PowerShell 和 Git Bash 的安装器测试覆盖取消、配置保留、旧版升级、切换后的全量备份、移除旧基线、关闭自动同步、本地笔记不变以及中文下载执行。未在 macOS 原生目录选择器与 plutil 上做实机验收。

已部署火影镜像 `lan-note-sync:installer-switch-20261115`。两个安装脚本在线响应与源码一致，网关与数据库健康，现有仓库/设备及文件统计保持一致；另一台用户电脑仍需执行新命令并确认切换。
