## 跨主机验收

在授权的 Tailscale 测试主机上，保留既有 Compose 项目、专用端口和两项绑定目录，从旧网关/数据库派生镜像升级到 0.4.0。此主机为 Ubuntu，未操作另一台 Rocky Linux / 1Panel 主机。

升级前导出并验证数据库备份，留存原部署配置和旧客户端的快照/正文哈希。升级后两个容器 healthy，旧设备令牌、serverId、文件头及正文哈希一致。

真实 CouchDB 上通过后台创建两个独立仓库、重命名、分别配对设备；两台设备运行 0.4 同步引擎完成原始字节往返，另一个仓库保持独立，跨仓库访问返回 403。规则生效后只同步允许的 Markdown，固定配置目录与自定义排除未进入文件列表；临时排除一个已同步文件后本地删除，不产生远端删除。活动记录正确关联设备，撤销设备后原令牌返回 401。

重启网关和 CouchDB 后再次验证旧文件哈希、仓库规则和设备撤销持久化，旧管理员浏览器会话失效。独立 Chrome 上完成远端登录、创建仓库、保存规则、邀请、活动、手机布局和退出流程，无页面异常。

## 范围与边界

管理台只显示服务端接受的文件修订，未收集客户端所有失败尝试。旧历史缺少时间时显示未知，最近活动只统计本次网关启动之后的请求。

所有设备应升级到 0.4 后再依赖排除策略。排除暂停同步，保留既有本地与远端内容；它不是访问控制或敏感数据清除机制。同步范围仍为桌面 Markdown，附件和移动端未纳入本次交付。
