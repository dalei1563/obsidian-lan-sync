## 0.4.2 确认按钮卡死修复（2026-11-09）

原生 Obsidian 1.15.0 + 真实 CouchDB 的空库首次下载复现了卡死：251 篇下载完成、同步状态落盘后，渲染进程进入无限微任务循环。Debugger 调用栈定位到宿主组件的 `then` 方法，CPU profile 与此一致。

原因是首次同步及冲突确认的按钮恢复回调隐式返回了 Obsidian ButtonComponent。该组件具备链式 `then`，Promise 会继续吸收返回的组件并重复解析自身。相关 `finally` 回调已改成显式 `void` 代码块，并检查插件是否卸载；设置页各恢复回调也增加了显式返回类型，避免同类回归。

回归模拟真实继承式 SDK thenable，覆盖首次确认成功、初始化失败后重试、冲突确认成功/失败，以及连接、预览、排除规则按钮的成功/失败恢复。危险场景放在独立 Node 进程，由父进程设置 5 秒超时；仅在内存中恢复旧缺陷时，测试能正确超时失败而不挂住主测试进程。

- 本地构建与 TypeScript 通过；92 项测试中 82 通过、10 按环境跳过、0 失败；配对/按钮专项 18/18 通过。
- 修复版使用全新空 Vault、新设备邀请、真实 CouchDB、原生文件系统和完整确认回调，从远端下载 251 篇笔记。
- 下载完成后持续 30 秒检查事件循环与同步状态，均正常响应；251 个文件、零待提交、零冲突。CPU profile 主要为空闲和正常磁盘操作，未出现旧版的 `then` 自解析循环。

## 范围与边界

管理台只显示服务端接受的文件修订，未收集客户端所有失败尝试。旧历史缺少时间时显示未知，最近活动只统计本次网关启动之后的请求。

所有设备应升级到 0.4 后再依赖排除策略。排除暂停同步，保留既有本地与远端内容；它不是访问控制或敏感数据清除机制。同步范围仍为桌面 Markdown，附件和移动端未纳入本次交付。
