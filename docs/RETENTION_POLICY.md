# LAN Note Sync 保留策略

默认永久保留服务端历史、正文、本地恢复快照、待处理队列和回收站；本项目不自动删除这些用户数据。

服务端历史修订是版本图的权威记录。当前实现把修订删除或父版本缺失视为损坏，客户端基线和历史恢复也依赖既有修订。随意按时间删除会破坏重建、冲突解决、离线设备对账及旧客户端兼容性。上述关于 CouchDB 的判断来自源码，**未在真实 CouchDB 上验证**。

如果将来需要清理服务端历史，应先完成版本图与检查点重设计，明确离线设备、冲突分支、幂等回执、删除标记和孤立正文的引用安全；制定可回滚迁移与一致性备份方案；规定新旧客户端和网关的协议兼容规则；然后在专用真实 CouchDB、跨设备及故障注入环境验证。现阶段只保留设计方向，不实现服务端删除。

## 容量与安全限制

历史正文、恢复快照、待处理队列与回收站可能持续增长。每个文件上限 5 MiB、逻辑文件数上限 10000 不构成历史空间上限。CouchDB 物理文件大小受压缩、索引和历史修订影响，不能简单等同于当前文件大小或各历史版本正文大小。系统回收站可能在 Vault 外；只统计 Vault 内 `.trash` 不能代表系统回收站全部占用。

估算示例：假定每天产生 100 个平均 20 KiB、内容均不同的新快照，30 天为约 58.6 MiB 的原始正文，6 个月约 351.6 MiB；实际占用还包括编码、索引、数据库碎片、备份和本地快照，可能更高。以实际增长趋势及磁盘剩余空间监测为准。

安全提醒：不要删除 `local-state` 或直接删除服务端数据库中的修订来释放空间。清理本地恢复快照会失去对应本机恢复副本，应先预览、确认并确保另有可用备份；云端历史不能保证覆盖所有尚未提交的本机内容。

插件设置中的容量检查以 1024 MiB 为单项默认告警阈值，可调整或设置 0 关闭提示；启动后及每六小时尝试一次，也可手动查看。增长速度按最近两次成功采样之间的差值折算，首次没有速度。历史值是当前仓库所有可读取修订引用正文按哈希去重后的逻辑字节数，包含当前正文，不包含孤立对象、编码、索引、碎片和数据库额外开销；它不能替代服务器磁盘占用。待处理队列统计的是正文解码后的逻辑大小，实际状态文件占用可能更高。Vault 内 `.trash` 不含系统回收站。历史并发变化时统计为近似值。服务未连接、查询失败或历史超过统计上限时应查看失败提示，不能把未知当作零。

插件只提供本机 `local-state/snapshots` 的显式清理：先检查并列出所有内容哈希命名且校验通过的快照，再由用户确认；预览后集合变化则拒绝执行。删除后此目录无法恢复已删除的本机副本，操作不涉及笔记、队列、回收站或服务端历史；删除过程中失败可能部分完成并会报告数量。该功能不自动运行。请先确认独立备份可用，尤其是未提交过的本机版本。实际 CouchDB 容量、跨平台系统回收站和物理磁盘占用均**未在真实 CouchDB 上验证**，需要单独监测服务器卷和系统回收站。
